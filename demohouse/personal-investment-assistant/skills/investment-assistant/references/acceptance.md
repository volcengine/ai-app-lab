# 验收清单

## 初始化

- [ ] 用户确认至少一只证券的名称、代码和市场。
- [ ] 每只证券有独立关注偏好，原词已写入 Profile。
- [ ] 盘后监控开关、时间、执行日和时区已经确认。
- [ ] Profile 权限为 `0600`，且不含凭证。
- [ ] 导入后首页不是空白关注列表。

## 工程

- [ ] `npm run check` 通过。
- [ ] `npm test` 通过。
- [ ] `npm run build` 通过。
- [ ] Skill 结构、语法和密钥扫描通过。
- [ ] 生产运行时由仓库内正式应用安装。

## 真实服务

- [ ] 只要求一枚 Agent Plan Key。
- [ ] `agent_plan_model` live probe 成功。
- [ ] `datapro` live probe 成功。
- [ ] `web_search` live probe 成功。
- [ ] `/api/health/ready` 返回成功且证明未过期。

## 首批报告

对每只证券运行：

```bash
node {baseDir}/scripts/acceptance.mjs --stock 证券代码 --seed
```

- [ ] 个股简评已生成并保存。
- [ ] 盘后风险摘要已生成并保存。
- [ ] 两类报告 ID 不同。
- [ ] 两类证据指纹不同。
- [ ] 两类报告未复用同一联网 URL。
- [ ] 个股简评含核心财务 DataPro 证据。
- [ ] 正文 evidence ID 都能在来源区找到。
- [ ] 联网来源包含真实标题、发布方、URL 和检索摘要。
- [ ] 每项用户偏好都有覆盖状态。
- [ ] 两类报告分别出现在对应历史记录中。

全量初始化使用：

```bash
node {baseDir}/scripts/acceptance.mjs --all --seed
```

完整回归使用 `--generate`，会为目标证券生成两次简评和一次盘后摘要，并额外验证连续简评的变化状态。该模式消耗更多真实额度。

## 报告内容

- [ ] 摘要是精简结论，不是下方段落拼接。
- [ ] 个股简评回答公司当前状态。
- [ ] 盘后摘要回答本次窗口内的变化。
- [ ] 两类报告正文、来源和历史相互独立。
- [ ] 没有“没有查到”“继续观察”等空泛占位段落。
- [ ] 财务数字、价格、百分比和日期均有证据支持。
- [ ] `review_required` 报告明确提示人工核对，不冒充已确认事实。

## 调度

- [ ] 保存监控设置后刷新页面仍一致。
- [ ] 下一次执行时间符合日期、时间和时区。
- [ ] “立即执行一次”生成监控报告与执行记录。
- [ ] 自动调度在实际测试时间触发，并生成自动执行记录。
- [ ] 自动与手动调用同一报告生成链路。
- [ ] 所有成功生成的监控报告都进入历史记录。

## 桌面端

- [ ] 首页显示全部证券和关注方向。
- [ ] 卡片按钮同一行，无异常换行。
- [ ] 详情页正文、引用来源和历史分区清晰。
- [ ] 生成时正文与来源区同时显示加载状态。
- [ ] 联网 URL 可以打开具体内容页面。
- [ ] 盘后设置可以修改和保存。
- [ ] 页面无溢出、重叠或控制台错误。

本轮开源验收只覆盖桌面端，不把移动端适配写成通过项。
