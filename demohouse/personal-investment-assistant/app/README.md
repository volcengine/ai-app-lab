# 个人投资助手项目

这是随“个人投资助手初始化”Skill 分发的完整应用源码。它不是静态演示：前端、API、SQLite、盘后调度、DataPro、豆包搜索和 Agent Plan 模型调用均包含在本项目中；任一必需真实服务不可用时，报告生成会明确停止，不会切换到 Mock 数据。

## 工程命令

```bash
npm ci
npm run check
npm test
npm run build
npm start
```

开发模式使用 `npm run dev`。默认生产地址为 `http://127.0.0.1:8788`，开发前端默认为 `http://127.0.0.1:5174`。

## 目录

- `src/web/`：React 前端。
- `src/server/app.js`：Express HTTP API 和路由入口。
- `src/server/providers/`：DataPro、豆包搜索和 Agent Plan 模型适配器。
- `src/server/services/`：报告、健康检查和盘后调度编排。
- `src/server/domain/`：证据、引用、Schema 与事实校验。
- `src/server/db/`：SQLite 持久化。
- `tests/`：单元与 API 集成测试。

## 两类报告

- 个股简评是按需生成的当前公司快照，使用当前行情、最新已披露基本面和关注方向相关公开信息。
- 盘后风险摘要同时区分当日市场异动、上一份盘后报告之后的新增公司事件，以及精确向前 168 小时的公司、行业和政策背景；近期背景不能冒充新增事件。
- 盘后没有新增公司事件时，仍可基于真实行情异动和近期背景形成观察；只有行情而没有任何可引用上下文时，只保存有具体行情证据、风险等级为 `unknown` 的市场观察，不保存空壳栏目。
- 查询、证据过滤和偏好覆盖按公司名称、证券代码、市场和用户原词动态生成，生产代码不包含演示公司的特判。DataPro 无法确认证券代码、来源不可信或语义审校失败时，报告必须标记为 `review_required` 或返回明确错误，不能拼接猜测性结论。
- “任意公司”指 DataPro 能返回可核验证券代码的 `CN`、`HK`、`US` 上市标的；任意字符串、未上市主体或第三方暂未覆盖的证券不会伪装成成功。单字、英文缩写、标点和长句偏好均按原词保留并逐项标记为已覆盖或待观察。
- 复合偏好必须在同一标题或同一句来源正文中完整命中全部语义要素；例如海外订单不能代替海外政策，材料技术路线不能代替原材料价格，也不能跨句拼接零散关键词。未覆盖偏好会使用公司、代码和用户原词继续精确检索；标记为 `covered` 的偏好必须在对应栏目出现实质正文，并且只引用自己的证据。最终仍无对应证据的 `watch` 偏好只保留为审计元数据，不显示“没有查到”或借用其他来源生成占位正文。
- 媒体评论、估值逻辑、推荐逻辑和“产业优势”等定性内容不会进入事件正文；过滤后某一类没有实质证据时直接省略栏目，前端仍按当前报告结构展示，不生成占位段落。
- 文娱活动、员工生活、品牌游记等非投资信息不会进入简评；单一媒体提供的车型售价、尺寸、续航、配置等参数不会写成公司事实。报告被语义审校拒绝时，本地用量日志会保存不含密钥的具体问题位置和原因。

## 配置与数据

不要把真实 Key 写入本项目或提交到 Git。初始化 Skill 默认只询问一枚 Agent Plan Key，将凭证写入 `~/.config/investment-assistant/credentials.env`，将数据库、日志、备份和生产运行时放在 `~/.local/share/investment-assistant`。模型、DataPro 和豆包搜索默认共用该 Key；`.env.example` 仅用于说明可选覆盖项。

修改源码后，应从 Skill 目录运行 `install.mjs`，重新执行检查、测试、构建和部署。运行时更新不会删除数据库、历史记录或凭证。

`acceptance.mjs --stock 证券代码 --seed` 为一家公司生成首份简评和盘后摘要；`acceptance.mjs --all --seed` 会为关注列表中的每家公司生成两类首批报告。`--generate` 是消耗更多额度的完整回归模式，会额外生成第二份简评并验证变化状态。

## 使用边界

本项目用于信息整理与研究辅助，不构成投资建议、收益承诺或交易指令。真实数据和模型结果仍需使用者结合交易所公告、上市公司披露等一手资料复核。
