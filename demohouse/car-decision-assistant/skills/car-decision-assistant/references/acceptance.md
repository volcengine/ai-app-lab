# 验收规则

## 离线门禁

```bash
npm ci
npm run release:verify
```

必须通过 Lint、TypeScript、生产构建、单元测试、公开文件扫描、Skill 结构和隔离安装。

## 真实 AI Native 应用开发底座

验证创建、关联读取、原子更新、并发版本冲突、恢复令牌轮换、旧 Cookie 失效、匿名隔离和删除。测试完成后不得残留测试项目。

## 真实 Harness 能力

三组场景覆盖：

- 杭州家庭通勤：座位、续航、辅助驾驶、本人体验、落地报价和城市数据。
- 上海个人纯电：纯电轿车、排除 SUV、续航、电耗、加速、配置、保险/保值待确认。
- 成都多人长途：6/7 座、增程/插混、续航、长途补能、多人体验和城市数据。

验收关注内容而非 HTTP：原文必须完整保存，车型只能确认一次，专业数据主体必须一致，销量必须保留城市、月份和口径，单项失败必须形成 partial 而非整体失败。

## 浏览器

从空白输入开始完成车型选择、结果查看、本人体验、报价、刷新、恢复和删除。检查网络错误、控制台 error、布局遮挡和错误提示可操作性。

## 不可替代证据

- 进程存在不能替代 Harness 能力验收。
- `success:true` 不能替代内容核验。
- 单元测试不能替代真实专业数据集调用。
- 历史截图不能替代当前 commit 的浏览器验收。
